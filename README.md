# ระบบจัดตารางเวรพยาบาล (Supabase + GitHub Pages)

ระบบจัดตารางเวรพยาบาลออนไลน์ของหอผู้ป่วยอายุรกรรมชาย โรงพยาบาลแหลมฉบัง ใช้งานได้ทั้งคอมพิวเตอร์ ไอแพด และมือถือ (โหมดกลางวัน/กลางคืน)
ข้อมูลเก็บบนคลาวด์ (Supabase) ใช้ร่วมกันทั้งหอผู้ป่วย แก้ไขพร้อมกันหลายเครื่องได้โดยไม่เขียนทับกัน

- เว็บไซต์: https://suphot3529.github.io/Hospital/
- เวอร์ชันล่าสุด: `2026.11.05.619` (หน้าจอแสดง V 1.0 · เลขเต็มดูได้ที่ชื่อแท็บเบราว์เซอร์)
- ตัวโปรแกรมทั้งหมดอยู่ในไฟล์ `index.html` ไฟล์เดียว (HTML/CSS/JS) ไม่ต้องมีเซิร์ฟเวอร์แยก
  ใช้ Supabase (แพ็กเกจ Free) เป็นฐานข้อมูล + ระบบล็อกอิน และ GitHub Pages เป็นตัวเปิดหน้าเว็บ

## เวรและกฎการจัดเวร (สรุป)

**รหัสเวร:** ช เช้า 08:00–16:00 · บ บ่าย 16:00–24:00 · ด ดึก 24:00–08:00 (ต่อจากบ่ายของวันเดียวกัน) ·
ชบ / ชด ควบ (นับ 2 เวร) · X หยุด · VA ลาพักผ่อน (= เวรเช้า) · T ประชุม/อบรม (= เวรเช้า) ·
P ป่วย (นับ 1 เวร แต่ไม่คิด OT) · ML ลาคลอด (= เวรเฉพาะวันทำการ)
ตัวดำ = เวรปกติ · ตัวแดง = เวร OT

**ขั้นตอนประจำเดือน:** เปิดรับ Request Day → ทุกคนลงคำขอ → บันทึก + ล็อก (คำขอลงตาราง 1) →
⚡ จัดอัตโนมัติ / แก้เอง → ✅ ยืนยันออกตาราง → ระหว่างเดือนแก้เวร/แลกเวร/แจ้งป่วยบนตาราง 2

**⚡ จัดเวรอัตโนมัติ** (เปิดใช้): ไม่แตะคำขอ Request Day / X / VA / ช่องล็อก → เติม ช บ ด ให้ครบอัตรากำลัง
(ผู้ช่วยฯ ก่อน แล้วพยาบาล · คนที่มีเวรน้อยสุดก่อน) → คนไม่พอใช้ควบ ชบ / ชด ในกลุ่มเดียวกัน · สรุปวัน/เวรที่ยังขาด

**กฎการจัดเวร** (ตาราง 📅 → กฎการจัดเวร · ตั้งค่าได้ทุกข้อ ซิงก์ทุกเครื่อง · ติดกฎ = แจ้งเตือน):

| หมวด | ค่าเริ่มต้น |
|---|---|
| ลำดับและความต่อเนื่อง | ดึก → เช้าวันถัดไป · ดึกติดกันไม่เกิน 2 คืน · ทำงานติดกันไม่เกิน 7 วัน |
| ภาระงานต่อเดือน | เวรรวมไม่เกิน 40 เวร · เวรควบไม่เกิน 18 วัน · วันหยุดอย่างน้อย 8 วัน |
| บุคลากรในเวร | ทุกเวรมีพยาบาลอายุงานขั้นต่ำ 3 ปี |
| Request Day | หยุดติดกัน · ขอเวรติดกัน · ขอดึก → เช้า · ขอเกินอัตรากำลัง · X/VA เต็มขอเวรได้ ด1 ช2 บ3 · จำกัด ด เดียว · หยุดเทศกาลสลับช่วง · X/VA วันศุกร์ท้ายเดือน |
| แลกเวร | แลกข้ามกลุ่ม · แลกวันลา · แลกย้อนหลัง · คำขอซ้อน · เตือน ดึก → เช้า / หัวหน้าขึ้นดึก / ทำงาน-หยุดติดกันเกิน |

**X/VA วันศุกร์ท้ายเดือน:** เปิดสวิตซ์ = ห้ามขอ X/VA วันศุกร์สุดท้ายของเดือน · คำขอที่ส่งไว้ก่อนเปิดสวิตซ์ยังอนุโลม

**อัตรากำลัง (👥):** ตั้งจำนวนคนต่อเวร ช/บ/ด แยก วันธรรมดา / เสาร์ / อาทิตย์ / วันหยุดราชการ
และแยก พยาบาล กับ ผู้ช่วยฯ/พนักงาน · ตั้งแยกได้รายเดือน (เดือนที่ไม่ได้ตั้ง = ค่าเริ่มต้น)

### ⭐ หัวหน้าหอผู้ป่วย — การนับในอัตรากำลัง

กฎการจัดเวร → **กำหนดการนับตามวันและเวร** (สวิตซ์ ช / บ แยกวันจันทร์–อาทิตย์ และวันหยุด)

- มีผลเฉพาะการนับอัตรากำลัง: วงแหวน · ⚡ จัดเวร · Request Day (ตรวจ "เวรเต็ม" ทั้งในแอปและฐานข้อมูล) · แลกเวร
- **ไม่เปลี่ยน** จำนวนเวร / ตัวดำ / ตัวแดง / OT ของหัวหน้า · หัวหน้ายังขึ้นเวรตามตาราง 2
- ปิดสวิตซ์ = นับหัวหน้าทุกเวรตามปกติ

## สูตรคิด OT

**OT (เวร) = เวรที่ขึ้นทั้งเดือน (เวรควบนับ 2) + VA + T + ลาคลอดวันทำการ − วันทำการ**
(วันทำการ = จันทร์–ศุกร์ ไม่รวมวันหยุดราชการ · X ไม่นับ · P นับในยอดรวมแต่ OT ไปที่คนที่ขึ้นแทน)

เวรปกติ (ตัวดำ) ต่อคน ตามจำนวนวันทำการของเดือน — ส่วนที่เกินในแต่ละประเภท = OT (ตัวแดง)

| วันทำการ | เช้า | บ่าย | ดึก |
|---|---|---|---|
| 18 | 6 | 6 | 6 |
| 19 | 6 | 6 | 7 |
| 20 | 6 | 7 | 7 |
| 21 | 7 | 7 | 7 |
| 22 | 8 | 7 | 7 |
| 23 | 8 | 8 | 7 |

ตัวอย่าง: ขึ้นจริง 38 เวร · วันทำการ 20 วัน → OT 18 เวร · แก้ตารางนี้ได้ที่ 💰 ตั้งค่า OT

**กติกาตัวแดง:**
- วันควบ ชบ / ชด แดงได้เวรเดียว (บ/ด แดง · ช ดำ)
- ⭐ หัวหน้าหอผู้ป่วย: เช้า จ–ศ และ VA = ตัวดำ · บ่าย/ดึกทุกวัน และทุกเวรวันเสาร์ อาทิตย์ นักขัตฤกษ์ = ตัวแดง
- 🤝 คนมาช่วยจากหน่วยงานอื่น: ทุกเวรเป็นตัวแดง

**อัตรา** (ค่าเริ่มต้น · แก้ได้ที่ 💰 ตั้งค่า OT · ตั้งรายบุคคลได้):

| ตำแหน่ง | ค่า OT / เวร | ค่าบ่ายดึก / เวร |
|---|---|---|
| พยาบาล อายุงาน 5 ปีขึ้นไป | 850 บาท | 360 บาท |
| พยาบาล อายุงานต่ำกว่า 5 ปี | 800 บาท | 360 บาท |
| ผู้ช่วยพยาบาล | 475 บาท | 120 บาท |
| พนักงานช่วยเหลือคนไข้ / อื่น ๆ | 450 บาท | 120 บาท |
| หัวหน้าหอผู้ป่วย | ตามอายุงาน | ไม่ได้ |

ค่าบ่ายดึก = ตัวดำ บ + ด ไม่เกิน 14 เวร

โปรเจกต์: `mpuvzknihminrxoxkeas` (URL และ publishable key ใส่ไว้ใน `index.html` แล้ว — key นี้เป็นค่าสาธารณะ ใส่ในหน้าเว็บได้)

| ตาราง `username_directory` | จับคู่ชื่อผู้ใช้ → บัญชีล็อกอิน (ล็อกอินด้วยชื่อผู้ใช้ ไม่ต้องใช้อีเมลจริง) |

ทุกตารางเปิด Row Level Security (RLS) — แต่ละหน่วยงานเห็นเฉพาะข้อมูลของตัวเอง

### ตั้งค่าที่ต้องทำใน Supabase (ครั้งเดียว)

1. **Authentication → Providers → Email:** ปิด "Confirm email"
2. **Authentication:** รหัสผ่านขั้นต่ำ 8 ตัว (ตั้งแล้ว)
3. **SQL Editor → New query:** วางเนื้อหาไฟล์ SQL → **Run** (เฉพาะไฟล์ใหม่ที่ได้รับ)
4. **Edge Functions:** ต้องมี `admin-reset-password` และ `thai-holidays` deploy อยู่

3. ทุกเครื่องรีเฟรชหน้าเว็บ (คอม: Ctrl+Shift+R · มือถือ: ปิดแท็บแล้วเปิดใหม่) หรือกด ⬇️ โหลดเวอร์ชันใหม่ ที่แถบแจ้งเตือน
   · เครื่องที่ยังเป็นเวอร์ชันเก่าจะถูกกันไม่ให้บันทึกทับข้อมูล

> ⚠️ **ห้ามแก้ `index.html` บน GitHub โดยตรง** (แม้แต่ตัวอักษรเดียว) — หน้าเว็บใช้ CSP แบบ hash
> ถ้าเนื้อหาสคริปต์เปลี่ยนแต่ hash ไม่ได้คำนวณใหม่ หน้าเว็บจะ **ขาวทั้งหน้า** · ให้แก้ผ่านไฟล์ที่ทดสอบแล้วเท่านั้น

**ปิดปรับปรุงระบบ:** แอดมินตั้งช่วงเวลาได้ — ทุกคนเห็นแจ้งเตือนตอนเข้าใช้ · ช่วงปิดผู้ใช้อื่นเห็นหน้าปิดปรับปรุงเต็มจอ (แอดมินยังเข้าได้)

## การใช้งานครั้งแรก / บัญชีผู้ใช้

1. แอดมินเข้าสู่ระบบด้วยชื่อผู้ใช้และรหัสผ่านของแอดมิน
2. 🔑 บัญชีผู้ใช้งาน → สร้างบัญชีให้แต่ละคน (เลือกบทบาท และผูกกับรายชื่อพยาบาล) → 📋 คัดลอกชื่อผู้ใช้ + รหัสผ่านแจ้งเจ้าของ
3. ผู้ใช้เข้าสู่ระบบ → ⚙️ บัญชีของฉัน กรอกรหัสเจ้าหน้าที่ / ตำแหน่ง / ปีที่เริ่มงาน (จุดแดงที่เฟือง = ยังขาดข้อมูล)

## ข้อควรรู้ด้านความปลอดภัย

- **ห้าม** ใส่ `service_role` key หรือรหัสผ่านใด ๆ ลงใน `index.html` หรือไฟล์ใดใน repo (repo นี้เป็นสาธารณะ)
- **อย่า** อัปโหลดไฟล์ SQL ขึ้น GitHub — โดยเฉพาะไฟล์ที่ใส่รหัสผ่านแล้ว (`supabase_fix_admin_login.sql` บรรทัด `v_pw`) และอย่ากด Save query ใน Supabase
- ผู้ใช้งาน (พยาบาล/ผู้ช่วยฯ) อ่านข้อมูลกลางได้ผ่าน `nsd_get` เท่านั้น — ฐานข้อมูลตัดตัวแดง / ตาราง OT / OT เทศกาล / ลายเซ็น ของคนอื่นออกก่อนส่ง (ใช้เครื่องมือนักพัฒนาก็ไม่เห็น) · การเขียนข้อมูลกลางและคำร้องถูกบังคับสิทธิ์ที่ฐานข้อมูล
- Content-Security-Policy: สคริปต์อนุญาตเฉพาะที่ระบุ hash + jsDelivr (ไลบรารีล็อกเวอร์ชัน + SRI) · รูปภาพเฉพาะ `self` / `data:` / `blob:`
- จำกัดการเรียกซ้ำ (rate limit) ที่ฐานข้อมูล เช่น เข้าสู่ระบบ 100 ครั้ง / 10 นาที / IP
- ไฟล์สำรองเข้ารหัส AES-256-GCM · รหัสไฟล์สำรองแอดมินตั้งเองในหน้าตั้งค่า (เก็บในฐานข้อมูล ไม่อยู่ในโค้ด)
- ออกจากระบบ → ล้างข้อมูลที่ค้างในเครื่อง
